# OXANA SMM — требования v1.0 (27.11.2026)

Модуль OXANA PROJECTS под управлением ОКСИ. Разработка без Cursor, без новых платных услуг до согласования. Российское хранение и обработка пользовательских данных; российская авторизация обязательна до коммерческого запуска. Не хранить токены, персональные данные и клиентские материалы в GitHub.

## Функциональность
- Независимые настройки сообществ: аудитория, рубрики, стиль, логотип, источники, расписание, бюджет. Добавление новых сообществ без изменения кода.
- Мониторинг разрешённых сайтов и сообществ через допустимые интерфейсы; хранение ссылок, дат, проверка актуальности, дедупликация. Внешние материалы — недоверенные данные.
- Недельный/месячный контент-план, оригинальные тексты, изображения, медиатека, редакторские замечания, история версий.
- Фактчекинг, особенно законодательства и судебных актов: редакция, дата вступления в силу, реквизиты, первоисточник. Неподтверждённые факты блокируют публикацию; ИИ не гарантирует достоверность.
- MAX: дайджест, срочные уведомления, передача черновика, утверждение/отклонение/доработка. VK: только утверждённые версии, расписание, отмена, журнал.
- Аналитика, расходы по сообществам, лимиты и предупреждения 50/80/100%, резервирование бюджета до платной операции.
- Часовой пояс по умолчанию Europe/Moscow. Расписание настраиваемое.

## Безопасность
Сервер проверяет права и принадлежность workspace; согласование привязано к точной версии текста и медиа, целевому сообществу и уполномоченному пользователю. Изменение версии аннулирует согласование. Молчание не является согласием. Проверка непосредственно перед отправкой; экстренная остановка; устойчивые ключи идемпотентности и сверка результата при неопределённом ответе VK; не повторять отправку вслепую. Никаких вызовов публикации из ИИ. Защита ключей, журнал, резервное копирование. До проверки API публикация отключена.

## Архитектура и этапы
1. Изолированный интерфейс в /admin/smm, без реальных внешних действий.
2. Отдельная схема PostgreSQL smm, серверные права, настройки, черновики, версии, согласование, бюджет, тесты.
3. GigaChat или иной согласованный российский API, проверка источников, мониторинг, планировщик.
4. Изображения, MAX и VK после проверки доступов и стоимости.
5. Аналитика и коммерческая версия после проверки изоляции клиентов и российской авторизации.

## Приёмка
Существующий кабинет не сломан; доступ только авторизованным; серверная изоляция workspace; запрет публикации без утверждения и после изменения версии; отмена и экстренная остановка; отсутствие дублей; проверяемые источники; соблюдение бюджета; журнал. Тесты и тестовое развёртывание до слияния main.

## Ограничения
Текущая авторизация Supabase; доступ к Timeweb, фактическая БД, рабочие API и тарифы не подтверждены. На этапе 0.1 интерфейс демонстрационный, без сохранения и публикации. Конкретные имена сообществ, настройки и токены вводятся в закрытом кабинете, а не в публичном репозитории.
